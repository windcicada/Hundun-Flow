# Re=3900 COAST/HUNDUN scientific-work rule

Status: rule frozen; equivalence receipt resealed to an immutable candidate
after two-step and output-off validation.

This rule defines the work unit for the v0.4 performance comparison before
COAST capability discovery. Discovery may fill the receipt or reject the
baseline; it may not weaken this rule. The machine-readable receipt template
is `v0.4-re3900-coast-equivalence-template.json`.

## Decision

The comparison unit is one complete, accepted physical time step of the same
discrete problem. Scientific work is matched by equation scope, physical time
advance, convergence obligations, terminal state gates and timer boundaries.
It is not matched by making native algorithm iteration counts equal.

HUNDUN must execute exactly two PISO pressure corrections. COAST must execute
its sealed native SIMPLE outer-iteration schedule. The COAST count and its
selection authority must be recorded before timed pairing and cannot be tuned
after observing timings. Every native iteration, assembly, linear solve, halo
and collective is charged to that product's step. A difference in the work
needed by the native algorithms to reach the common accepted state is part of
the performance result, not a reason to delete work from one side or add a
third HUNDUN correction.

The full2 work unit is exactly two accepted physical steps: backward Euler
startup followed by one BDF2 step, ending at `t=0.012`. Full20 is exactly 20
accepted physical steps, ending at `t=0.120`. A counter or end-time convention
that executes fewer accepted steps is invalid. Each product has one accepted
step/time commit authority; output scheduling may neither advance nor relabel
an accepted state.

## Common discrete problem

Both sides must advance transient continuity, three momentum components and
sensible enthalpy with the same inert ideal-gas closure, local absolute
pressure, `drho/dp` at fixed enthalpy/composition and the full BDF density
defect. They use the same mesh, active solid/fluid geometry, reference state,
initial fields, boundary values, fixed `dt=0.006`, BE startup followed by BDF2,
Vreman wall treatment, material properties and registered second-order method
families. Matching a label is insufficient: the sealed receipt must bind
resolved constants, masks and method descriptions or hashes. A missing COAST
capability rejects the baseline; HUNDUN's scope is not reduced to fit it.

## Linear work

For every iterative linear solve, the terminal authority is an independently
recomputed FP64 true residual:

`r = b - A x`, `||r||_2 <= max(atol, rtol ||b||_2)`,

using the current exact assembled operator, right-hand side and solution on
the active algebraic rows. A recursive or preconditioned residual alone may
not terminate a solve. Equivalent equation scaling is allowed only when the
receipt records the deterministic pullback to the common physical residual.
For pressure, `atol=1e-8`, `rtol=1e-6`, and the per-solve cap is 500. Audit
cadence is recorded but need not be equal: checking more or less frequently is
native solver cost, while a true-residual audit at termination is mandatory.
Reliable residual replacement and mixed-precision solution accumulation are
allowed only when terminal authority uses the actual high-plus-low solution
against the exact physical operator snapshot taken before solver scaling.

Restart length and other bounded Krylov-subspace policies are native solver
choices, not cross-product work-matching knobs.  Each candidate must freeze
them before timing; changing one creates a new candidate and requires a new
equivalence receipt.  The resulting orthogonalization, operator,
preconditioner, communication and true-residual-audit work remains inside the
product timer.  It may change native iteration counts, but it cannot justify
adding or deleting a PISO/SIMPLE iteration or relaxing the common terminal
residual obligation.

HUNDUN may impose a supplemental native convergence audit after, and only
after, its canonical FP64 true-residual criterion has passed. A rejected
supplemental audit continues the same pressure linear solve within the frozen
500-iteration cap; it does not add a PISO correction, replace or relax the
global L2 criterion, or make an attempted state eligible. Every evaluation,
rejection and the resulting Krylov/MG/communication work remains inside the
HUNDUN step timer and must be reported by the runtime evidence schema. COAST
is not required to copy this native audit cadence: it must instead complete
its sealed SIMPLE schedule and pass the same independent common terminal
audit. The independent post-step audit remains mandatory for both products,
even when HUNDUN has already evaluated the byte-identical continuity cell
formula during PISO2 convergence.

An equation implemented as a direct or registered diagonal update is marked
not applicable rather than being forced to perform a fictitious Krylov solve.
If it is iterative, its norm, tolerance, cap and per-solve terminal residual
must be sealed. Each step records solve counts, iterations, initial/final true
residuals, termination reasons and cap hits. A cap hit rejects the step.

## Common terminal audit

After native coupling work and before a state is eligible for timing evidence,
the same independent evaluator must audit the candidate fields. "Same" means
that both product binaries compile the byte-for-byte identical, hashed ISO C
binary64 evaluator source; product wrappers may only gather local inputs,
perform the specified matching MPI reductions, and call that evaluator. It
applies the HUNDUN v0.4 dimensionless definitions for local EOS defect and full-BDF cell
continuity defect, plus the applicable closed-mass and pressure-gauge or
outlet-closure checks. All four limits are `1e-6`. The evaluator and its inputs
are immutable hashed evidence. Passing a product's internal status alone is
not sufficient.

The state is ineligible if it is rejected, retried, non-finite, reaches a
linear iteration cap, omits a registered native iteration, or fails any common
terminal gate. Full20 also excludes the policy's startup/warmup steps from
statistics.

## Timer boundary

Each rank starts immediately before the first native hot-step operation and
stops immediately after the common terminal audit and accepted-state commit.
The step authority is the maximum of those local intervals, reduced only after
timers stop. The interval includes all equation, solver and communication
work. It excludes process/case initialization, Visit, Restart, serialized
screen output, evidence serialization and the post-stop timer reduction.
Output-off applies through finalization: no Visit, Restart, serialized screen,
monitor or other scheduled result artifact may be emitted; only the sealed
evidence channel is permitted.
Formal pairing cannot begin until COAST demonstrates this same max-rank
boundary; a rank-0-only or whole-launch timer is not equivalent.

## Stage 5 boundary

Stage 5/combustion code and validation are outside this nonreacting
comparison. They may not change the equation scope, input bytes, timer,
executable or process inventory of either paired product. The Cartesian v0.4
compatibility seam remains `FrozenExecutionGraph`/`ContributionPlan` with
`C1 -> transport -> PISO1 -> C2 -> PISO2`. This rule records only that seam;
it neither imports Stage 5 code nor claims that Stage 5 has been integrated
into the Re=3900 candidate.

## Seal and failure rule

The JSON template stays `UNSEALED` until every capability, method, tolerance,
timer and immutable identity field is resolved. Sealing requires exact input,
binary, source, geometry, thermophysics, MPI, CPU/affinity and performance
policy identities. Any unresolved required field, unavailable common terminal
evaluator, or COAST physics mismatch is a fail-closed rejection of formal
pairing, not permission to reinterpret scientific work.
