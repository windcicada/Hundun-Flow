### 已确认根因与修复边界

- 初始投影：锚定后的代数 L2 残差 `2.8534e-10` 已满足线性相对阈值，
  但去掉锚点约束后的实际通量散度最大值 `3.92249e-10` 仍超过物理要求。
  使用现有 `LinearConvergenceAudit`，仅在生产 FGMRES 接近停止时检查真实通量；
  独立 PCG oracle 保持独立，最终审计及状态的一致提交与回退不变。
- 重启：单 rank 的所有状态字段逐字节相同；192 个差异全部位于 IBM 界面，
  且只是 `-0.0 → +0.0`。没有更改生产重启算法。测试对非界面通量继续逐字节比较；
  MPI 重复界面允许两种零符号，但绝不允许非零穿透通量。
- `central2`：原先被错误地绑定到 limited_central2 专用缓存；只去掉缓存后还出现
  `2/5784`，因为 prepared Schur 路径也依赖该缓存。两处路由同时修正后原时间精度测试通过。
  当前 Re3900 的 limited_central2 路径不受此修复影响。
- 正常结束重建 ApplicationRunReport 漏掉末步求解记录；改为保留现有报告。
  每次提交后立即更新步号和时间，并添加输出/资源/推进终止阶段，不把写入失败当数值失败。
- `valid_boundary` 在 noexcept 中分配 unordered_set，导致异常绕过既有配置阶段 catch。
  分配失败扫描通过公共 CaseCompiler 逐点触发真实分配，验证全 rank 状态一致和失败时不发布模型。
- 路径比较：调试器栈定位到 `within` 的 filesystem path 组件迭代；本机 libc++ 的组件赋值
  也有 noexcept 分配。对已经规范化的绝对路径改用不分配的本机字符串比较，并检查分隔符边界；
  不绕过目录安全校验。路径规范化本身允许 bad_alloc 传播到公开入口的 Status 转换。
- app 的 Visit/Screen/Monitor/Restart/Evidence 路径和文本构造都纳入本地阶段 catch，再做全体状态汇总。
  `getrusage` 本地失败也先汇总。新测试通过真实 ApplicationService 入口，在指定 rank 注入 bad_alloc；
  原先报 MPI_Allreduce 错序，修复后六种阶段均一致返回，已提交步数仍为 1。
- 自适应对流时间尺度：`ProductDriver::constrain_convective_time_limit` 读取已接受密度、质量面通量
  和各单元实际体积，跳过固体单元。ApplicationService 在每步提出 dt 前调用；由现有 TimeController
  进行全局最小值和一次 CFL 缩放，无流出时不增加限制。保留显式 `advance(limits, report)` 接口，
  固定 dt 不扫描、不改变。新增公共接口测试覆盖速度缩放、零速度、更严格外部上限和 1/2/4 分区。
  **本次只补对流项**；黏性/热/组分/声学输入仍由现有调用者提供，不能宣称所有物理尺度已接入。
