# FGMRES 后续列显式恢复实验：拒绝进入生产

基线为 `3e1e1ca`（数值/观测源码 `7c03a54`）。目标窗口已测得 unsafe 丢列成本，
本次只在独立工作区试验：后续列负递推范数时，也使用已有显式重正交化，
而不立即放弃方向并重启。没有改物理方程、门槛、restart 或生产迭代上限。

**结论：该最小改法未通过局部验收，不启动它的 Re3900 性能窗口或长测。**

公开 `solve_fgmres()` 接口配合 67 单元非对称三对角算子，系数为
`scale * (-1.2, 3, -0.7)`，已知正弦解；独立全局真残差与解误差作 oracle。
采用合法的单位预条件器，restart=12、rtol=1e-10、atol=1e-26，
不注入负范数、不调用私有 norm helper。

| scale | 原路径迭代 / A / M | 直接保留方向（同 80 次预算） | 结论 |
|---|---|---|---|
| 1e-8 | 44 / 53 / 44，收敛 | 80 / 94 / 80，达到上限仍拒绝；内部真残差约 4.52517e-17 | 回退到原 caller x，没有错误发布，但可接受性退化 |
| 1e-6 | 44 / 61 / 44，收敛 | 65 / 78 / 65，收敛 | 工作增加 |
| 1e-4 | 37 / 51 / 37，收敛 | 36 / 43 / 36，收敛 | 一个子例改善，不足以通过 |

中间 32 次局部预算实验中，原路径和候选都失败；它只是工作预算假设被否定，
不是原路径新增缺陷，也不是允许修改 Re3900 的迭代上限。最终回归保留原有
80 次公开调用预算，能够拒绝本次简单移除丢列分支的退化。

原路径可以稳定求解这三个系统，说明“unsafe 丢列数量多”不自动等于保护错误。
当前只证明简单保留方向不具有足够鲁棒性，没有据此确认正范数残差、基正交性、
移位相消或可变预条件中的某一项是唯一根因。若进一步设计，需独立检验这些量，
不能继续堆恢复启发式或将未验算法混入默认生产路径。
