# 本地计算工作台

工作台连接已登记的真实运行目录，提供运行概览、通用收敛曲线、日志、算例配置查看和场数据截面。启动与恢复使用配置的原生程序和 MPI 启动器；输入配置在界面中以只读方式展示。

## 启动

在仓库根目录执行：

```bash
./ui/run
```

脚本检查本地依赖，执行 `npm run build --prefix ui`，随后由 FastAPI 同时提供 API 和 `ui/dist` 页面。浏览器打开 <http://127.0.0.1:8765>。

端口通过参数或环境变量选择，参数优先：

```bash
./ui/run --port 8875
HUNDUN_UI_PORT=8875 ./ui/run
```

首次配置需要 Python 3.11+、Node.js 20.19+（20.x）或 22.12+，以及 npm。在仓库根目录安装依赖：

```bash
python3.11 -m venv ui/.venv
ui/.venv/bin/python -m pip install -r ui/requirements.txt
npm ci --prefix ui
```

`ui/requirements.txt` 固定 Python 依赖版本，`ui/package-lock.json` 固定前端依赖。启动脚本仅检查和使用本地环境；安装命令由操作者执行。

## 路径配置

启动前可设置以下环境变量。所有路径均由后端展开并解析为绝对路径。

| 环境变量 | 用途 | 当前默认值 |
|---|---|---|
| `HUNDUN_CASE_ROOTS` | 算例／运行根目录，多个目录用逗号分隔 | `/home/wyf/code_dev/cases` |
| `HUNDUN_PROGRAM` | 原生程序可执行文件或运行包装器 | `/home/wyf/code_dev/flow/check/pkg/run` |
| `HUNDUN_MPI` | MPI 启动器 | 原生程序同目录的 `mpirun` |
| `HUNDUN_UI_STATE` | 任务登记、界面发起的运行及后处理图像目录 | `~/.local/state/hundun-ui` |
| `HUNDUN_UI_PORT` | 界面服务端口 | `8765` |

例如，使用浅层目录组织个人工作区：

```bash
export HUNDUN_CASE_ROOTS="$PWD/cases"
export HUNDUN_PROGRAM="$PWD/bin/run"
export HUNDUN_MPI="$PWD/bin/mpirun"
export HUNDUN_UI_STATE="$PWD/state"
./ui/run
```

`HUNDUN_UI_STATE` 应位于源运行目录之外。后处理图像写入其中的 `plots`，界面发起的新任务写入 `runs/r…`。任务登记保存在 `jobs.json`，其中包含命令、来源和进程身份。配置原生程序时，应同时准备其运行时库及匹配的 MPI 环境。

## 使用流程

1. **选择或登记运行。** 后端发现允许根目录中的算例和运行记录。通过界面登记路径时，填写该范围内的真实运行目录；登记完成后查看步数、时间步长、MPI 信息和日志。元数据以输出文件实际提供的字段为准。
2. **查看通用指标。** 收敛图以时间步为横轴，显示所选运行提供的连续性、能量、EOS 等指标；计算耗时、CFL 和线性迭代次数按记录展示。图例可切换曲线，对数轴展示正值。缺失记录保留间隔，图注说明统计窗口及数据来源。
3. **查看输入。** 算例页展示已登记 `case.json` 的网格、时间推进、边界和模型配置。需要调整输入时，在外部编辑器中修改对应算例，再刷新页面查看。
4. **发起新算。** 选择已登记算例、推进步数和 MPI 进程数。后端先调用原生 `check`，再创建独立运行目录，记录完整启动命令。界面显示启动请求与实际运行状态，步数和日志随原生输出更新。
5. **请求输出。** 对身份匹配的活跃原生进程，界面发布原生 `output` 请求。程序在其控制点写出场文件，实际完成记录来自 `control.jsonl` 和输出目录。
6. **保存并停止。** 界面发布原生 `stop` 请求，程序在安全控制点保存检查点后退出。“请求已提交”与“保存停止完成”分别显示；以程序回执和 `Restart/current` 为完成依据。
7. **恢复计算。** 选择具有完整检查点及唯一算例关联的运行，填写本次继续推进的步数和 MPI 进程数。后端检查算例和 `restart-info`，在新的运行目录读取源 `Restart`。兼容性由原生加载过程检查，原运行保留为恢复来源。

界面仅向与配置程序、输出路径和进程身份匹配的运行提供控制操作。结束浏览器或界面服务时，已经派发的计算进程继续按其自身状态运行；需要结束计算时使用“保存并停止”。

## 场数据后处理

后处理读取 `Visit` 下的 legacy VTK、VTK XML 和多分区索引，展示实际可用时间步及变量。速度幅值、压力和温度列在前面，随后列出真实输出中的其他数值标量，例如密度、焓、组分和 TCR 字段。选择变量和 X／Y／Z 法向；位置可用区域中心或以米为单位的指定坐标。点击“生成截面”后，后台读取相交分区并生成 PNG，可直接下载原图。

变量列表根据最新完整输出的首个分区生成，所选时间步在绘图时核实字段。额外字段采用单分量标量，ghost、固体标记和 ID 字段作为辅助信息处理；速度采用三分量向量的幅值。原生 `rho` 和 `h` 分别标注 kg/m³ 与 J/kg，其余额外字段显示“原始单位”，PNG 标注 `original units`，API 返回 `unspecified`。API 的额外变量标识为 `field:<真实字段名>`，图注保留原始字段名。

图像保留物理坐标、字段名称、单位、真实步号和时间。压力扰动字段与静压字段分别标识；时间来自场文件或运行记录，缺少时间记录时图上显示对应状态。已有 IBM 和 ghost 标记参与遮罩；输出未附固体标记时会注明。截面采用 VTK 平面切割，节点值在切出的三角面上取平均，先剔除固体及 ghost 单元，保留流体区域。

生成任务逐个执行，缓存按源文件身份、变量和截面参数区分。当前资源限额为单帧 3 GiB、单分区 256 MiB、1200 万点、80 万截面三角形和 120 秒处理预算。超限、缺变量、正在写出的分区或读取期间发生变化的文件都会返回具体状态。原始场文件保持只读。

## 远程使用

服务绑定服务器的 `127.0.0.1`。先在服务器上启动工作台，再从本机建立 SSH 转发：

```bash
ssh -L 8765:127.0.0.1:8765 user@server
```

本机浏览器打开 <http://127.0.0.1:8765>。使用其他端口时，同时调整启动端口和转发参数。API 校验本机主机名及写请求来源，页面和 API 由同一个地址提供。

## 检查入口

从仓库根目录运行：

```bash
bash -n ui/run
ui/.venv/bin/python -m unittest ui.test_api ui.test_plot -v
npm run build --prefix ui
```

这些检查覆盖界面模块和构建。实际计算能力的判断仍以选定算例、程序版本、原生日志、检查点及相应数值验证证据为依据。

## 当前范围与接续开发

首期页面包含工作台、算例、网格与边界、计算监看、后处理和报告中心。
通用指标为已接受步、物理时间、时间步长、CFL、推进耗时、方程指标、
质量与能量收支、MPI 信息及内存高水位。力系数、火焰位置、出口温度、
喷雾粒径等专用分析按照算例需求作为后续插件接入。

后续工作按以下顺序推进：

1. 将 `jobs.py` 的类型化任务操作复用于自动化工具入口，保持相同请求编号、
   进程身份和原生控制回执。
2. 增加算例配置 Schema 表单、模型能力检查、几何及边界区域预览。
3. 扩展物理量与统计窗口选择、探针／积分面、三维流线和等值面。
4. 增加远程主机适配器及队列调度；当前远程使用采用在计算端部署并转发本机端口。

2026-09-22 的界面检查覆盖生产构建、20 项 API 检查、7 项场读取／绘图检查，
以及桌面和手机布局、六页切换、搜索、输入错误反馈、监测与图像导出。
真实 128 分区场成功生成截面；独立 8³ 小算例以 2 个 MPI 进程完成新算、
场输出、保存停止和新目录恢复，第 1 步保存后恢复至第 2 步，两个进程组均以 0 退出。
这些记录对应工作台数据与控制链路；大算例的物理验收沿用各自的验证范围。

已启动工作台时，可运行只读浏览器检查：

```bash
npx --prefix ui playwright install chromium
node ui/test_ui.mjs
```

`HUNDUN_UI_URL` 指定服务地址，`HUNDUN_BROWSER` 指定本机 Chromium 可执行文件。
需要覆盖真实场绘图时，设置 `HUNDUN_TEST_FIELD_RUN` 为 `/api/runs` 中的运行编号；
浏览器检查读取运行、切换页面并导出报告，计算控制由上述独立小算例覆盖。
