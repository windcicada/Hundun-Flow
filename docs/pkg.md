# 原生算例独立运行包

S22（2026-09-16）新增 `tools/v04_case_pack.py`，将原生输入、
Restart、正式程序、Linux 运行库、OpenMPI 组件、Cantera SDK、
许可记录、源码归档与构建清单装入同一目录。输入和依赖在复制
前后逐项核对，完整校验后发布目录。文件清单记录 SHA-256、
权限及内部链接，运行包附带 `pack.py --verify` 入口。

## 源码与启动身份

此次打包检查定位并修正了三个交付问题：

- 宿主 glibc 2.31 与程序所用 glibc 2.35 存在 ABI 差异，运行包
  采用匹配的私有 ELF 加载器及完整依赖。OpenMPI 使用
  `--noprefix`，使子进程在自己的加载器选定之后使用对应运行库。
  最小复现从单进程 `/bin/true` 的段错误恢复为正常退出。
- 原源码归档构建将 Git 身份写为 `unavailable`，运行随后在
  `runtime_identity` 阶段返回 `10505`。`.git_archival.txt` 经
  Git `export-subst` 保存原提交和源码树，CMake 使用项目本身的
  Git 工作区或该归档身份；源内容摘要另行记录。嵌套构建中的
  外层仓库身份通过项目根目录匹配来区分。
- 显式调用加载器时，`/proc/self/exe` 指向加载器。原生身份读取
  现在按 `AT_PHDR` 找到应用 ELF 映射，核对设备号和 inode，
  再对打开的应用文件计算 SHA-256，并检查读取期间的文件状态。
  直接启动、显式加载器及含空格的新文件名均获得实际程序哈希。

三项定向检查通过，总耗时约 2.04 秒，覆盖运行 ELF 身份、归档
身份及打包文件约定。程序哈希检查先复现加载器哈希误报，再通过
修正后的相同入口。文件检查包含内部链接、权限、原始数据保留和
六类异常；归档元数据检查包含有效身份与五类异常／缺失记录。

## 本次验证范围

使用已有 16³ 合成组合算例：CN/BE、outer_corrected、静态 IBM、
Vreman、两场 ESF 双状态、煤油四步化学、THICK_EX 和气液共同交换。
从原生第 3 步恢复，采用原 `1e-9 s` 时间步。

运行包在 Linux 5.4、宿主 glibc 2.31 环境完成 1→2 进程续算。
随后在独立 Ubuntu 22.04 根文件系统中，以包内源码归档和 Cantera
SDK、已声明的 Clang 15／libstdc++ ABI1／ThinLTO 工具链重新构建。
该环境仅挂载运行包与构建工具，开发工作区和原 Cantera 安装路径
保持隔离。重建程序完成单进程第 4 步，包内程序从第 4 步完成
四进程第 5 步。四进程功能检查限定于两个 CPU，并显式允许 MPI
空闲让出；本次结果用于可移植性和正确性验收。

| 检查 | 结果 |
|---|---|
| 源码重建单进程／包内双进程，第 4 步完整状态 | 402,944 个值，最大归一化差 `1.9739162e-14` |
| 同一对照的面通量 | 最大绝对差 `5.2939559e-22 kg/s` |
| 包内四进程第 5 步／既有同进程参考 | 完整状态与面通量逐值相同 |
| 方法元数据、颗粒原生记录 | 精确一致 |
| 三次接受步归一化质量／能量缺陷 | 最高 `1.2636e-16 / 1.0144e-16` |
| 组分／元素收支相对缺陷 | 最高 `5.0658e-8 / 5.4459e-8`，通过 `1e-6` 门槛 |
| 运行证据中的程序 SHA-256 | 与实际包内程序、重建程序各自一致 |

该运行包验证对应上述合成组合；GTMC 和 624CF 实场打包接续
各自的实场续算与迁移出口，完整 A—E 验收继续执行。

```sh
tar -xzf hf.tgz
cd hf
python3 pack.py --verify .
./run check case
./mpirun -n 2 --bind-to none ./run run case --restart restart --output out --steps 1 --restart-interval 1
./mpirun -n 2 --bind-to none ./run run case --restart out/Restart --output next --steps 1 --restart-interval 1
```

`./build` 使用源码归档与包内 SDK 重建；构建环境安装 CMake 3.21
及以上、Ninja、Clang 15／lld、GCC 11 libstdc++ 开发文件与
OpenMPI 4 开发文件。运行和原生恢复使用包内程序及运行库。
