# HUNDUN-FLOW v0.4 target hot loop

Status: revised performance-first stage schedule, 2026-08-20; binding becomes immutable per
compiled case at Task 18

The production schedule is machine-reviewable through the following exact stage chain:

```text
begin attempt -> thermophysical predictor from committed flux history
-> C1 model contribution seam -> update thermo/transport and closed-mass pressure reference
-> momentum predictor -> PISO corrector 1 -> C2 model contribution seam
-> PISO corrector 2/final flux
-> terminal EOS/continuity/mass/gauge audit
-> diagnostics snapshot decision -> collective commit/rollback
```

No production stage may allocate from the heap, parse text, query STL/BVH geometry, search
donors, discover peers, create MPI requests, rebuild an uninvalidated resource, or introduce a
second writer for an authoritative field.

## Persistent resource boundaries

- `EBTopology`, `BoundaryStencilPlan`, and `SurfaceQuadraturePlan` are initialization products
  for static geometry. Hot stages borrow them and cannot rebuild them.
- Halo metadata, pack/unpack spans, buffers, persistent MPI requests, and compact IBM remote
  donor gathers are compiled after all stage ghost sets and donor reaches are known. `begin`
  starts one registered exchange; `finish` is the only ghost/donor-revision publication point.
- Each linear system keeps separate `Symbolic/CoarseningPlan`, current fine/coarse
  `ExactNumericState`, `PreconditionerSetupState`, and `SolverWorkspace` identities. A stage may perform only the refill/setup action explicitly
  allowed by the frozen graph and the resource's invalidation tuple.
- Accepted and trial values use handle rotation. Cache publication is pending until collective
  commit; rollback never restores the full field by copying it.

## Corrector cache rule

```text
momentum diagonal + rho/source/constraint/numeric-BC revision -> rAU
rAU + consistent diagonal revision -> optional rAtU
momentum numeric revision + current trial U + pressure convention -> HbyA
reciprocal diagonal + face-rho/EOS revision -> pressure face coefficient
current HbyA + face coefficient + current trial/committed flux history
  + BDF/p_ref/gauge/geometry/numeric-BC -> phiHbyA
pressure equation flux -> only final face-mass-flux writer
pressure gradient from the same solve -> final U update
```

Corrector 1 changes trial `U/phi`. Therefore corrector 2 rebuilds or revision-recertifies
`HbyA/phiHbyA`; a successful certificate must include every dependency above. `rAU/rAtU`
alone may be reused if and only if their momentum/density/diagonal/constraint/boundary coefficients
are unchanged.

## Consensus invariants

1. No accepted revision, final flux, or snapshot becomes visible before the final collective
   commit.
2. Each structured halo or compact IBM donor gather publishes validity only after `finish`; interior work may overlap an active
   exchange, but boundary work may not.
3. Thermophysical prediction names committed face-flux history revisions; corrector 2 is the
   only current-attempt final-flux writer, and all later accepted consumers name that revision.
4. A local exception, invalid state, solver failure, residual failure, conservation failure,
   or snapshot-staging failure contributes to the same collective rollback decision. Status is
   reduced only at registered epochs and piggybacked on unavoidable collectives when legal.
5. Repeating a stage with unchanged structural and coefficient identities must produce zero
   symbolic rebuilds, zero stale exact/coarse numeric data, zero unauthorized preconditioner
   setups, and zero workspace allocations.
