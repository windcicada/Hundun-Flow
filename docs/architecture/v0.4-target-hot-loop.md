# HUNDUN-FLOW v0.4 target hot loop

Status: frozen stage schedule, 2026-08-13

The production schedule is machine-reviewable through the following exact stage chain:

```text
begin attempt -> update thermo/transport -> momentum predictor
-> PISO corrector 1 -> PISO corrector 2/final flux
-> enthalpy -> inert species/passive scalars
-> diagnostics snapshot decision -> collective commit/rollback
```

No production stage may allocate from the heap, parse text, query STL/BVH geometry, search
donors, discover peers, create MPI requests, rebuild an uninvalidated resource, or introduce a
second writer for an authoritative field.

## Stage schedule and publication points

| Order | Stage | Halo begin/interior/finish/boundary | Cache and authority publication | Collective consensus |
| ---: | --- | --- | --- | --- |
| 0 | `begin attempt` | No halo. Rotate accepted handles into trial handles; clear pending cache publications and the compact attempt log. | Publish no accepted revision. Capture the accepted revision tuple, time mode, and attempt id; select backward Euler for startup/retry or BDF2 when eligible. | One attempt-start consensus confirms the same `dt`, time mode, execution-graph id, and failure-free precondition on every rank. |
| 1 | `update thermo/transport` | `begin(thermo inputs)` -> update owned interior -> `finish` publishes input ghost revisions -> update physical-boundary/ghost-dependent cells. | Build pending `rho`, `T`, `cp`, `mu`, `lambda`, sound-speed, Mach, and `(partial rho / partial p)_(h,Y)` caches keyed by local absolute pressure, enthalpy, composition, model, geometry, and BC revisions. | 6 | `inert species/passive scalars` | For registered fused groups: `begin(final mass flux and scalar reads)` -> interior assembly/solve -> `finish` -> physical-boundary work. | Every inert species and passive scalar consumes the same final face-mass-flux revision. Snapshot I/O uses preallocated staging. | Diagnostics are read-only. Publish a pending snapshot descriptor only if the schedule and state-validity gates pass; diagnostics cannot change solver authority or cache revisions. | Global reductions establish extrema, conservation evidence, snapshot eligibility, and whether any rank reported failure. |

On any failure, discard trial handles, pending caches, compact log, and pending snapshot; accepted storage is untouched. | Exactly one all-rank commit decision. Success commits everywhere; failure rolls back everywhere, chooses the collective retry policy, and prevents partial output publication. |

## Persistent resource boundaries

- `EBTopology`, `BoundaryStencilPlan`, and `SurfaceQuadraturePlan` are initialization products
  for static geometry. Hot stages borrow them and cannot rebuild them.
- Halo metadata, pack/unpack spans, buffers, and persistent MPI requests are compiled after all
  stage ghost sets are known. `begin` starts one registered exchange; `finish` is the only
  ghost-revision publication point.
- Each linear system keeps separate `SymbolicPlan`, `NumericState`, `HierarchyState`, and
  `SolverWorkspace` identities. A stage may perform only the refill/rebuild action explicitly
  allowed by the frozen graph and the resource's invalidation tuple.
- Accepted and trial values use handle rotation. Cache publication is pending until collective
  commit; rollback never restores the full field by copying it.

## Corrector cache rule

```text
momentum numeric revision -> rAU
rAU + consistent diagonal revision -> rAtU
momentum numeric revision + current trial U -> HbyA
current HbyA + current trial U/phi + time/geometry/BC -> phiHbyA
pressure equation flux -> only final face-mass-flux writer
pressure gradient from the same solve -> final U update
```

Corrector 1 changes trial `U/phi`. Therefore corrector 2 rebuilds or revision-recertifies
`HbyA/phiHbyA`; a successful certificate must include every dependency above. `rAU/rAtU`
alone may be reused if and only if their momentum/diagonal/constraint/boundary coefficients
are unchanged.

## Consensus invariants

1. No accepted revision, final flux, or snapshot becomes visible before the final collective
   commit.
2. Each halo publishes ghost validity only after `finish`; interior work may overlap an active
   exchange, but boundary work may not.
3. All equation consumers name the stage-4 final face-mass-flux revision.
4. A local exception, invalid state, solver failure, residual failure, conservation failure,
   or snapshot-staging failure contributes to the same collective rollback decision.
5. Repeating a stage with unchanged structural and coefficient identities must produce zero
   symbolic rebuilds, zero unauthorized hierarchy rebuilds, and zero workspace allocations.
