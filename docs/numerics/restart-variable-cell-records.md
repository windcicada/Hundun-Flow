# Restart V5 变长单元记录

喷雾的注射、破碎、迁移和蒸发会改变每个单元中的 parcel 数量。原生 Restart V5
为这种状态提供单元归属的变长字节载荷。它只负责持久化和重分区；模型必须校验
parcel 身份、材料、几何归属和生命周期，再与气相共同安装。

## 公共视图

`RestartSnapshot.cell_records` 使用非零 `identity`、`record_bytes=0`，并提供
`variable_cell_bytes`：每个本地单元一个 u32 字节数，x 最快排序。`values` 是按同样
顺序拼接的载荷。长度和必须等于载荷总长度；允许空单元和整个分区均为空。
普通固定宽度记录仍写 V4，V1–V4 的布局不变。

`RestartExpected` 同样使用非零模型身份和零固定宽度。读入后的 `RestartImage`
提供 `cell_record_lengths` 和拼接后的 `cell_records`。模型字节的内容版本由 identity
绑定，整数不得先转换成浮点数。

## 编码

V5 沿用 V4 的公共头和方法历史签名，公共头中的固定记录宽度为 0。
rank 文件在两层面通量之后、完整性校验字之前增加以下内容：

| 内容 | 编码 |
| --- | --- |
| 总载荷字节数 | 小端 u64 |
| 每个本地单元的载荷长度 | `local_cell_count` 个小端 u32 |
| 拼接载荷 | 原始字节，不添加对齐填充 |

manifest 的 rank 目录保持原有 40 字节记录。文件总大小结合固定字段布局、单元长度表
和公共头，可在读入载荷前计算该源块所需的内存上限。模型身份、长度表和载荷均受
已有 manifest/rank 完整性校验保护。

## 读取与预算

首先按原流程分工检查每个源 rank 文件。对于 V5，目标 rank 再读取与其单元范围
相交的源块，统计目标单元长度。长度前缀和给出精确目标载荷大小；通过预算检查后
才分配目标载荷并恢复字段与模型记录。多一次冷路径读取避免预分配全局 parcel
载荷，也不限定每个单元的 parcel 数量。

预算包含保留的旧图像、新字段与通量、长度表、临时偏移表、最大源块的原始/解码
缓存及目录。失败不会替换调用者已有的 RestartImage。

公共读写测试覆盖 1→4、4→1、4→4 分区、不同占用率、全空集合、超过 2^53 的
整数载荷、单 rank 长度/身份错误和预算边界。此格式入口尚未等同于喷雾产品接线；
当前产品 TCR 专用恢复仍要求 V4，V5 产品证据与模型安装将在喷雾入口中接入。
