# 产品喷雾持久状态合同

此合同定义 native spray 状态适配器的 Restart V5 单元记录。完整产品还须在同一个
气相事务中调用这些准备、验证和发布步骤；记录适配器本身不接受气相时间步。

记录身份由已冻结产品模型提供，须绑定气相/液体资产、注射器、RNG、算法与模型配置。
外层 V5 负责单元长度、分块完整性、内存预算和重分区；每个非空单元的模型记录如下。
全部整数为无符号小端，实数为 IEEE binary64 的精确位模式，不以实数存储整数。

| 字节偏移 | 内容 |
| --- | --- |
| 0 | u64 已接受步数，与 native checkpoint 的 step 相同 |
| 8 | u32 parcel 数量 |
| 12 | u32 注射器数量 |
| 16 | u32 内嵌 TCR 字节数，只能为 0 或 120 |
| 20 | u32 记录版本，当前为 1 |
| 24 | 可选 120 字节 TCR 历史，沿用 product-tcr-history.md 的格式 |
| 随后 | 每 parcel 144 字节，按完整 ID 排序 |
| 最后 | 每注射器 24 字节，按冻结配置中的顺序 |

每 parcel 的 18 个八字节位置依次为：ID high/low、位置 x/y/z、速度 x/y/z、
单滴质量、直径、multiplicity、温度、液体材料身份、owner global cell、年龄、
TAB 形变、TAB 形变率、u64 breakup ordinal。ID、材料身份、owner 和 ordinal 均为整数。
每注射器包含 u64 ID、残余质量和 u64 next ordinal。注射器只附着在其冻结原点的单元。

无 parcel、无注射器且无 TCR 的单元允许零长度记录；启用 TCR 时每个单元都有记录。
Typed parcel 和字节缓冲分别预分配 accepted/trial 两套。注射器的恢复同样先暂存，
在气相及全部模型预检通过后调用无分配的统一发布；任何后续拒绝都必须丢弃所有候选。

局部适配器验证记录长度/步数、材料身份、owner 单元、完整 ID 的局部唯一性、有限值、
TAB、注射器配置/余量与容量。组合恢复还必须调用 TCR 的 typed history 验证。
产品安装者仍须在发布前检查实际几何位置/液体物性及全局 ID 唯一性；记录解码不能替代它们。

验证包含实际 RestartWriter/Reader 的 1→4 与 4→1 分区恢复，比较完整模型字节和
注射器状态；局部测试验证大整数、共同暂存/撤销以及 TCR 末期拒绝后的原状态保持。
